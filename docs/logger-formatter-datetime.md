## 实现思路

Formatter 在构造阶段解析 pattern，将连续文本合并为字面量项，将占位符转换为格式项。每次 format 按顺序向输出缓冲区追加内容，不清空已有数据。整数通过 `std::to_chars` 写入栈缓冲区，减少临时字符串。

LogRecordView 的字符串字段使用 `std::string_view`，不拥有底层数据。调用方必须保证字符串在格式化结束前有效；异步日志队列需要另行管理数据所有权。

支持的指令：

| 指令 | 内容 |
| --- | --- |
| `%m`、`%p`、`%c` | 消息、日志级别、logger 名称 |
| `%r` | 耗时，单位毫秒 |
| `%t`、`%F`、`%N` | 线程 ID、协程 ID、线程名称 |
| `%f`、`%l` | 文件名、行号 |
| `%d`、`%u` | 本地日期时间、六位微秒部分 |
| `%T`、`%n`、`%%` | 制表符、换行、百分号 |

例如 `%d.%u%T[%p]%T%m%n`。默认日期格式为 `%Y-%m-%d %H:%M:%S`。

日期部分从记录已有时间戳取秒，使用 thread_local 缓存；秒数变化时才执行本地时间转换和 strftime。微秒部分独立输出并补齐六位。日期转换包含 Windows 的 localtime_s 和 POSIX 的 localtime_r 分支；独立实验目前仅使用 POSIX 接口。

## 实验运行与解释

```bash
cmake -S . -B /tmp/pans-build -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/pans-build --target test_datetime_consume -j2
./bin/tests/test_datetime_consume 1000000
```

可执行文件按仓库 CMake 配置输出到源码树的 `bin/tests/`。程序先测空循环，再测逐次转换、按秒缓存，打印扣除空循环后的总纳秒数及比值；这些数值不是 ns/op。

当前是探索性实验，不能据此承诺固定加速倍率：

- 两组分别使用 time 和 system_clock::now，时钟调用并不一致。
- 格式化结果未消费，micros 未使用；空循环和部分计算可能被优化掉。
- 缺少预热、重复采样、分位数和缓存未命中次数统计。
- 没有覆盖实际缓冲区追加、完整 formatter 或日志写入成本。
- CTest 无参数运行时只输出用法并返回成功，不会执行性能循环。

后续应统一时间输入、消费输出、分开测量缓存命中和跨秒更新，再加入完整格式化路径的基准。

## 已知限制与后续工作

本次补充注释和说明，以下行为仍保留在实现中，未作为已完成修复：

1. parse 检查了 `{...}`，但没有把内容赋给 item_format，因此自定义日期格式实际被忽略。
2. 日期缓存是函数内 static thread_local，同一线程上的不同实例共享状态；支持自定义格式前需增加格式身份或采用隔离的缓存上下文。简单改成共享对象成员会引入并发访问问题。
3. 日期缓存只有 20 字节，仅适用于默认日期字符串；长格式需要容量和失败处理策略。
4. last_second 初值为 0，首次格式化 epoch 秒 0 会命中尚未填充的缓存，需要独立有效标记。
5. epoch 之前的秒数转换向零截断，与微秒的非负归一化可能不一致，应统一使用向下取整语义。
6. 格式或运行时时区变更需要缓存失效策略。

优先修正正确性与测量方法，再评估固定格式数字转换、复用输出缓冲区、异步格式化和批量写入。是否需要更复杂的优化应以实际热点为依据。
